# Hex Tunnel 1.0.0-rc.20

Fecha: 2026-08-05

## Corrección principal

El instalador visual redefine `dpkg` para enviar la salida técnica al registro. El helper de Cloudflare WARP utilizaba `$(dpkg --print-architecture)` dentro de una sustitución de comandos; bajo el modo visual, esa salida quedaba redirigida y la fuente APT podía terminar con una opción vacía `arch=`.

APT rechazaba esa fuente, el helper la retiraba y ejecutaba una actualización de recuperación con los repositorios de Ubuntu. La última actualización parecía correcta en pantalla, pero el helper devolvía el código del primer fallo y la instalación terminaba con un mensaje genérico.

## Cambios

- La fuente WARP adopta el formato oficial de Cloudflare:

  ```text
  deb [signed-by=/usr/share/keyrings/cloudflare-warp-archive-keyring.gpg] https://pkg.cloudflareclient.com/ noble main
  ```

- Se elimina la dependencia de `dpkg --print-architecture` al crear la fuente.
- La fuente escrita se valida byte por byte antes de ejecutar APT.
- Si `apt-get update` rechaza Cloudflare, se muestra el diagnóstico completo antes de retirar la fuente.
- La instalación de `cloudflare-warp`, el registro, el modo proxy, el puerto 40000 y la conexión devuelven errores específicos.
- El runtime heredado solo cambia propietario y permisos de `/var/log/syslog` cuando el archivo existe; Ubuntu 24.04 con journald deja de mostrar errores `No such file or directory`.

## Regresión cubierta

La prueba WARP reemplaza `dpkg --print-architecture` por un comando que falla deliberadamente. La instalación simulada debe continuar porque el helper ya no depende de esa salida. También se comprueba que la fuente no contenga una opción `arch=` vacía.

La prueba del runtime generado exige la guarda de `/var/log/syslog` y rechaza la instrucción heredada incondicional.
